Каталоги данных сервера

Переменная FEDMES_DATA_DIR задаёт единый каталог состояния. В нём сервер создаёт fedmes.sqlite3 и подкаталог media. QR-программа обязана использовать тот же каталог, иначе приглашение будет записано в другую базу и клиент не сможет подтвердить устройство.

Поток подключения устройства

  1. Администратор создаёт одноразовое приглашение программой fedmes-qr.
  2. QR содержит публичный URL, фиксированное имя пользователя, одноразовый токен и срок действия.
  3. Клиент сканирует QR, создаёт локальную идентичность устройства и обращается к серверу.
  4. Сервер проверяет приглашение, привязывает устройство и выдаёт сессию.
  5. Повторное применение использованного токена отклоняется.

Поток сообщений

Клиент подготавливает и шифрует содержимое, сервер сохраняет транспортные данные и зашифрованные полезные нагрузки, а другие устройства получают изменения через API синхронизации. Медиа сохраняются отдельно в каталоге данных и доступны только через серверные проверки доступа.

HTTP и HTTPS

Production Rust-сервер не выставляется напрямую в Интернет. На Ubuntu он слушает 127.0.0.1:8008. Nginx принимает соединения 443, завершает TLS и проксирует запросы на локальный Rust backend. Отдельная Windows server-сборка в 2.0.1 удалена: production backend единый и работает на Ubuntu.
